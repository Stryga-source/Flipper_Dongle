# Flipper Dongle

Flipper Dongle — отдельный USB-адаптер на ESP32-S3, который превращает Bluetooth HID-профили Flipper Zero в обычную USB-клавиатуру и мышь для ПК.

На компьютере не нужны драйвер, отдельная программа или специальное приложение для Flipper. Донгл работает как BLE HID Host со стороны Flipper и как стандартное USB HID-устройство со стороны компьютера.

## Текущий статус

**Первая тестовая версия: v0.5.5**

Проверено и работает:
- Flipper Zero `Bluetooth Remote -> Keyboard`
- ввод с клавиатуры BLE -> ESP32-S3 -> USB HID
- мышь BLE -> ESP32-S3 -> USB HID
- BadUSB / BadKB в BLE-режиме
- корректные press/release без залипания клавиш
- USB-отчёты мыши
- синхронизированная передача TinyUSB HID
- несколько сохранённых BLE HID-сопряжений
- CDC COM-порт для отладки

**Следующая тестовая версия: v0.5.6 — ожидает проверки**

v0.5.6 исправляет гонку состояний при сбросе сопряжения и повторном нажатии кнопки pairing. Пока эта версия не считается основной, пока не будет несколько раз проверена на реальном железе.

## Железо

Основная тестовая плата:
- Waveshare ESP32-S3-LCD-1.47

Неоригинальный `Pocket-Dongle-S3-0.96` — рабочий USB HID-таргет. На фактической плате esptool обнаружил ESP32-S3, flash 16 МБ и встроенную PSRAM 8 МБ. Полный образ заводской flash сохранён вне Git. Пользователь подтвердил работу клавиатуры и мыши через Flipper Bluetooth Remote, BadUSB и сцен на экране 160×80. Кнопка BOOT проверена на GPIO0. Распиновка microSD и наличие отдельного статусного LED пока не проверены. У донгла нет физического переключателя HID/DRIVE; подробности в `docs/hardware/T_DONGLE_CLONE.md`.

Стек разработки:
- ESP-IDF 6.1
- NimBLE
- TinyUSB

## Архитектура

```text
Flipper Zero
   |
   | BLE HID
   v
ESP32-S3 Flipper Dongle
   |
   | USB HID Keyboard + Mouse
   v
ПК
```

При этом Flipper может оставаться подключённым обычным Bluetooth-профилем к телефону, а HID-профиль при необходимости используется донглом.

## BLE-профили

Проект учитывает, что у Flipper может быть несколько разных HID-личностей.

Обычные примеры:

```text
Control <имя Flipper>   -> Bluetooth Remote
BadUSB <имя Flipper>    -> BadUSB / BadKB BLE
```

У этих профилей могут быть разные BLE-адреса, поэтому для них могут требоваться отдельные сопряжения.

v0.5.5 хранит до 4 BLE HID bond-профилей.

## Управление сопряжением

Целевая логика:
- короткое нажатие BOOT: одно явное окно поиска/сопряжения
- сохранённый bond: автоматическое переподключение к доверенному HID-профилю
- длинное нажатие BOOT: удалить все сохранённые HID-сопряжения
- после удаления bond: оставаться в ожидании до нового короткого нажатия BOOT

Кандидат v0.5.6 отдельно исправляет гонку между очисткой bond, асинхронным BLE disconnect и новым запросом pairing.

## USB-режимы

Текущая отладочная сборка показывает:
- HID Keyboard
- HID Mouse
- CDC COM-порт для логов

Планируется два финальных варианта:
- **Debug**: HID + CDC COM
- **Release**: только HID, без видимого COM-порта

Позже рабочее BLE HID-ядро будет объединено с уже проверенным аппаратным переключателем HID/DRIVE и режимом USB MSC для microSD.

## Сборка

Windows PowerShell:

```powershell
$env:IDF_TOOLS_PATH="C:\Espressif\tools"
C:\esp\v6.1\esp-idf\export.ps1

idf.py set-target esp32s3
idf.py build
idf.py flash
```

Сборка Pocket-Dongle из корня репозитория:

```powershell
idf.py -B build-pocket -DPOCKET_DONGLE=ON build
idf.py -B build-pocket -DPOCKET_DONGLE=ON -p COM23 flash
```

`COM23` — порт загрузчика в проведённом тесте; номер порта может измениться.
Пользователь считает HID-таргет рабочим. Повторные стресс-тесты сопряжения,
microSD и плакат с PIN ещё требуют отдельной проверки.

## Статус версий

### Экран Pocket-Dongle

Pocket-сборка показывает полноэкранные сцены с дельфином 160×80: три кадра поиска, найденный Flipper, клавиатуру, мышь и BadUSB. Во время поиска значок Flipper остаётся на месте. Для неизвестного HID-отчёта есть рисунок джойстика, но передача USB-джойстика **не реализована**.

Во время BLE-сопряжения шестизначный код выводится прямо на плакате в руках дельфина. В изображении нет постоянного PIN: для режима display-passkey текущий NimBLE helper использует `123456`, а при numeric comparison берётся код из BLE-события. Логика сопряжения этим изменением не переделана.

Новая прошивка Pocket записана с проверкой хэшей. После подключения без удержания BOOT пользователь подтвердил показ новых картинок, анимацию поиска, переключение сцен клавиатуры и мыши и работу BadUSB. Плакат с кодом сопряжения ещё не проверен на железе. Сборка Waveshare также проходит.
